# 微信聊天记录整理

把导出的微信聊天记录清洗成统一结构的数据，方便用 Excel、pandas 或 AI 做后续分析。
单个脚本，只用 Python 3.8+ 标准库，不联网。

## 隐私先说清楚

- 脚本只读写本机文件，不上传任何数据。
- **这个仓库是公开的。** 原始导出请放在 `wechat-chat/data/`，结果默认写到 `wechat-chat/output/`，
  这两个目录已加入 `.gitignore`，不会被提交。不要把真实聊天记录放到别的目录再提交。
- 聊天记录里也有对方的信息。要分享或交给第三方分析时，建议加 `--anonymize --mask-pii`，
  并且不要附带 `name_map.csv`（它能把代号还原成真名）。

## 第一步：导出聊天记录

微信本身没有“导出为文本或表格”的功能。官方的“聊天记录迁移与备份”生成的是只能恢复回微信的加密备份，不能直接读。

### iPhone + Windows：从 iPhone 备份里导出（推荐）

用开源工具 [WechatExporter](https://github.com/BlueMatthew/WechatExporter) 读取 iPhone 在电脑上的备份。
它只读备份文件，不碰正在运行的微信。它是第三方工具，不是微信官方的。

1. **准备**
   - 电脑剩余空间要比 iPhone 已用空间大（这是整机备份）。
   - WechatExporter 只能导出**手机上现有的**记录。删过的、换机时没迁移过来的，导不出来。
   - 电脑上装 Apple 官方的「Apple 设备」应用（Windows 11 在 Microsoft Store 里）或 iTunes。
2. **把 iPhone 备份到电脑，不要加密**
   - 用数据线连接电脑，iPhone 上点“信任此电脑”。
   - 在「Apple 设备」或 iTunes 的备份设置里，选“将 iPhone 上所有数据备份到此电脑”，
     **不要勾选“加密本地备份”**（WechatExporter 不支持加密备份）。如果以前开过加密，取消勾选时要输入当时设的备份密码。
   - 点“立即备份”，等它完成。
3. **下载 WechatExporter**
   - 只从项目官方的 GitHub Releases 页面下载 Windows x64 版本，然后解压。
   - 运行时提示缺少 dll 的话，装一下它 README 里给的 Visual C++ 运行库。
4. **导出**
   - 运行 `WechatExporter.exe`。上方“iTunes备份目录”一般能自动找到。找不到的话：
     在「Apple 设备」里点“管理备份”，右键备份，选“在资源管理器中显示”；
     常见位置是 `%USERPROFILE%\Apple\MobileSync\Backup`（Apple 设备 / 商店版 iTunes）
     或 `%APPDATA%\Apple Computer\MobileSync\Backup`（官网版 iTunes）。
   - 菜单 **格式 → 文本**。
   - 在对话列表里**只勾选要导出的对话**。
   - 选一个输出目录，开始导出。导出的文件结构是 `输出目录\你的微信名\对话名\index.txt`，每个对话一个。
5. **收尾**：不加密的备份里有整部手机的数据。导出完成后，建议在「Apple 设备」里删掉这份备份，
   或者重新打开加密再备份一次。

把整个输出目录复制到 `wechat-chat\data\`，然后看下面的“第二步”。

### 其他途径

- **电脑版微信 + 数据库解密工具**（留痕/MemoTrace、PyWxDump、chatlog 等）：这类工具里，PyWxDump、chatlog
  已经删库；能用的版本普遍只支持旧版电脑微信，要降级才行。网上流传的打包版来源无法核实，风险较高，不推荐。
- **消息不多时**：手动复制，整理成下面任意一种 TXT 格式。

## 第二步：运行

先用自带的合成示例试一下（`samples/` 里的人名和内容都是编的）：

```bash
cd wechat-chat
python3 wechat_clean.py samples --me 小明
```

处理自己的数据（Windows 上把 `python3` 换成 `python`）：

```bash
# WechatExporter 导出的整个目录（每个对话一个 index.txt），--me 填你的微信昵称
python3 wechat_clean.py data --me 我的昵称

# 单个文件；--me 填你在记录里显示的名字
python3 wechat_clean.py data/小红.txt --me 我的昵称

# 整个目录，所有文件合并成一份
python3 wechat_clean.py data/

# 同一个会话分几次导出、时间段有重叠：合并并去掉重叠部分
python3 wechat_clean.py data/小红-2023.txt data/小红-2024.txt --chat 小红 --me 我的昵称

# 只要 2024 年以后的消息，去掉系统提示，人名换成代号，遮盖手机号等
python3 wechat_clean.py data/群聊.csv --me 我的昵称 --start 2024-01-01 \
    --drop-system --anonymize --mask-pii
```

运行时会打印每个文件识别出的格式（TXT 的行格式，或 CSV/JSON 的列对应关系）。请核对一下，
不对的话用 `--format` 或 `--col-*` 手动指定。

## 支持的输入

### TXT：自动识别 5 种行格式

| 格式 | 示例 |
|---|---|
| 名字 (时间):内容（WechatExporter 的文本导出） | `小红 (2024-03-05 08:00:00):今天几点去？` |
| 时间 名字，内容在下一行 | `2024-03-01 08:15:02 小红`<br>`早呀，今天还去健身房吗？` |
| 名字 时间，内容在下一行 | `小红 2024/3/2 9:03`<br>`今天练了多久？` |
| [时间] 名字: 内容 | `[2024-03-02 20:00:00] 小红: 晚饭吃了什么` |
| 时间 名字: 内容 | `2024-03-02 20:00:00 小红：晚饭吃了什么` |

多行消息会合并成一条；第一条消息之前的标题、分隔线会跳过（计入“跳过 N 行”）。
输入是目录时，里面认不出的文件（比如 WechatExporter 生成的对话列表）会跳过并在摘要里列出，不会中止。

WechatExporter 格式的几处特殊处理（依据它的文本模板源码）：

- 首行“小红 - 微信聊天记录”作为会话名。它每个对话的文件都叫 `index.txt`，所以不从文件名取会话名。
- 撤回、拍一拍（`System Message: …`）、“你已添加了…”等系统提示单独占一行，没有名字和时间。
  这些行单独记为一条系统消息，时间沿用上一条消息。
- 引用回复（`「小红：原文」`、分隔线、回复）拆成 `content`（回复）和 `quote`（被引用的内容）。
- 转发的聊天记录（`<< 标题` 到 `标题 结束 >>` 之间）整段并入转发它的那条消息，类型记为“聊天记录”，
  里面的消息不算进这个对话的统计。
- 它的转账消息后面不换行，下一条消息会接在同一行，脚本按已出现过的发送人名字把它拆开。

### CSV / TSV / JSON / JSONL：按列名自动匹配

列名不区分大小写，忽略下划线和空格。JSON 可以是对象数组，也可以是带 `messages` / `data` 等数组字段的对象。

| 字段 | 能自动识别的列名 | 必需 |
|---|---|---|
| 时间 | StrTime、时间、发送时间、消息时间、datetime、time、date、日期、CreateTime、timestamp | 是 |
| 内容 | StrContent、content、内容、消息内容、消息、msg、message、text | 是 |
| 发送人 | sender、发送人、发送者、发言人、from、Remark、备注、NickName、昵称、name | |
| 是否自己发送 | IsSender、is_self、is_send、is_sender、是否自己、是否发送者 | |
| 类型 | type_name、类型、消息类型、msg_type、Type | |
| 会话 | 会话、聊天对象、群名、chat、conversation、room_name、TalkerId、StrTalker、talker | |

- 时间和发送人如果匹配到多列，按上表顺序逐列尝试，取第一个有效值；日期和时间分在两列也能拼起来。
- 时间写法：Unix 秒或毫秒、`2024-01-05 09:03:07`、`2024/1/5 9:03`、`2024年1月5日 下午3:04`、ISO 8601。
  不带时区的时间按原样当作本地时间；Unix 时间戳默认按北京时间换算，可用 `--utc-offset` 改。
- 类型的数字代码按微信本地数据库的常见取值映射：1 文本、3 图片、34 语音、42 名片、43 视频、47 表情、
  48 位置、49 分享卡片（链接、文件、小程序等）、50 通话、10000/10002 系统。这是根据公开资料整理的，
  不同版本可能有出入；不认识的代码记为 `类型N`，不会丢弃。
- 文件编码 UTF-8、UTF-16、GBK/GB18030 自动识别。

## 参数

| 参数 | 作用 |
|---|---|
| `-o, --out 目录` | 输出目录，默认是脚本旁边的 `output/` |
| `--format` | `auto`（默认）/ `txt` / `csv` / `json` / `jsonl` |
| `--me 名字` | 你在记录里显示的名字，多个用逗号分隔。记录里把你显示为“我”的，就写 `--me 我` |
| `--chat 名字` | 会话名。不填时依次用数据里的会话列、文件开头的标题（如“小红 - 微信聊天记录”）、文件名 |
| `--start` / `--end` | 只保留这段日期（含首尾两天），格式 `YYYY-MM-DD` |
| `--drop-system` | 去掉系统提示、撤回、拍一拍 |
| `--text-only` | 只保留文字消息 |
| `--anonymize` | 人名、会话名换成代号，对照表存为 `name_map.csv` |
| `--mask-pii` | 遮盖正文里的手机号、身份证号、银行卡号、邮箱 |
| `--utc-offset 小时` | Unix 时间戳换算用的时区，默认 `8` |
| `--col-time` 等 | 自动识别不对时手动指定列：`--col-time` `--col-sender` `--col-content` `--col-self` `--col-type` `--col-chat` |

## 输出

| 文件 | 内容 |
|---|---|
| `messages.csv` | 主表，按时间排序。带 BOM，Excel 直接打开中文不乱码 |
| `messages.jsonl` | 同样的数据，一行一条 JSON，方便程序读取 |
| `chat.txt` | 按会话分组、每天一个小标题的可读文本，适合直接阅读或交给 AI |
| `summary.md` | 统计摘要：发送人、消息类型、按月 / 小时 / 星期分布、消息最多的日子 |
| `summary.json` | 同样的统计，外加每个输入文件的解析情况 |
| `name_map.csv` | 仅 `--anonymize` 时生成：原名与代号对照表。**不要外传** |

`messages.csv` 的列：

| 列 | 说明 |
|---|---|
| `id` | 序号（排序后） |
| `conversation` | 会话名 |
| `datetime` / `date` / `time` | 本地时间 |
| `weekday` / `hour` | 星期（周一…周日）、小时（0–23） |
| `sender` | 发送人 |
| `is_self` | 1 = 你发的，0 = 别人发的，空 = 无法判断 |
| `type` | 文本、图片、语音、视频、表情、文件、链接、位置、名片、红包、转账、通话、聊天记录、分享、撤回、拍一拍、系统 |
| `content` | 内容。非文字消息保留原始内容（可能是 `[图片]` 占位符，也可能是 XML） |
| `quote` | 引用回复时被引用的内容，其他消息为空 |
| `length` | 文字消息的字数（不含引用），非文字消息为 0 |
| `timestamp` | Unix 时间戳（秒） |

## 自动判断的规则

- **消息类型**：没有类型列时按内容判断。`[图片]` `[语音 0:04]` `[文件: a.pdf]` `[位置] 地名` 等占位符开头的，
  按括号里的第一个词归类（`[微笑]` 这类微信表情代码仍算文字）；“微信转账 …”记为转账；
  “某某撤回了一条消息”记为撤回；“某某 拍了拍 某某”记为拍一拍；“加入了群聊”“你已添加了”等记为系统。
  像“我拍了拍他的肩膀，说加油”这种带标点的普通句子仍算文本。
- **去重**：只去掉**不同文件之间**重叠的消息（时间、发送人、类型、内容都相同）。同一个文件里的重复保留——
  只精确到分钟的导出里，一分钟内连发两张图本来就是两条一模一样的记录。
- **自己发的消息**：优先用数据里的“是否自己发送”列，这类消息的发送人统一记为 `--me` 的第一个名字（没给就记为“我”），
  因为数据库类导出里的“备注/昵称”列常常是对方的信息。没有这一列时，发送人与 `--me` 中任一名字相同的算你发的。
- 发送人为空、又不是你发的消息记为“对方”；系统类型的消息发送人记为“系统”。
- **文本清理**：微信在 @某人 后面插入的特殊空格（U+2005）换成普通空格，去掉零宽字符和首尾空白；空消息丢弃。
- **匿名化**：发送人换成“我 / 成员01 / 成员02…”，会话换成“会话01…”（单聊的会话名就是对方名字时，用同一个代号）。
  正文里出现的这些名字（两个字及以上）按字面替换。注意两点：只替换发送人和会话名，聊天里提到的其他人不会被替换；
  昵称恰好是常用词（比如“哈哈”）时，正文里的这个词也会被换掉。
- **敏感信息遮盖**：18 位身份证号、16–19 位连续数字（按银行卡号处理，可能误伤订单号这类长数字）、11 位手机号、邮箱。

## 已知局限

- 只用合成的示例数据测试过，没有拿各种导出工具的真实文件验证。WechatExporter 的格式是照它的模板源码模拟的。
  如果你的文件识别得不对，把列名或开头几行的格式（内容可以打码）发给我，我来适配。
- WechatExporter 对最新版 iOS 微信的兼容情况我没法验证；它的 issue 里有人报告过导出乱码。
- WechatExporter 文本导出里，链接、小程序分享只剩标题，看起来和文字一样，会被算作文字消息。
- 没有类型列时，“撤回 / 拍一拍 / 系统”是按措辞判断的，极少数格式相同的普通句子会被误判。
- 内容另起一行的 TXT 格式里，如果某条消息中有一行恰好以“日期 时间”开头（比如“2024-03-01 10:00 开会”），
  会被误认为是新消息的抬头。
- 不支持 HTML 导出。
